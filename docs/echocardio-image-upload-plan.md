# 심초음파 이미지 업로드 & AI 수치 추출 기능 계획

> 작성일: 2026-05-16  
> 상태: 아이디어 정리 완료 / 구현 보류

---

## 배경

`/app/hospital/[hos_id]/echocardio` 에는 현재 3가지 검사 입력 방식이 있다.

| 모드 | 설명 |
|---|---|
| 섹션 | 정규화된 입력 순서에 따라 입력 |
| 목록 | 모든 항목을 사용자 지정 순서대로 나열 (분류 없음) |
| 가이드 | 템플릿 기반 가이드 뷰와 연결된 항목 입력 |

여기에 **4번째 입력 방식 — 이미지 업로드 + AI 추출**을 추가하는 것이 목표.

---

## 원하는 기능 요약

1. 심초 장비 화면 스크린샷 / 리포트 이미지를 업로드
2. AI가 이미지를 분석해 측정 항목과 수치를 추출
3. 우리 프로젝트 필드에 해당 항목이 있으면 결과값 자동 매핑
4. UI: 업로드 이미지(좌) + 추출 결과(우) 나란히 표시
5. DB 매핑 테이블로 장비별 용어·단위 차이를 교정

---

## 기술 평가 결론

### 가능 범위

**장비 측정 리포트 스크린샷** (GE Vivid, Philips EPIQ, Mindray 등 측정값 화면)  
→ Vision LLM + OCR으로 **실용적 수준(90~95%)** 가능

**초음파 영상 자체 (B-mode, M-mode 이미지에서 수치 측정)**  
→ 현재 기술로 실용적이지 않음. 전문 AI 모델(Stanford EchoNet 등) 수준 필요. 수의 데이터셋 부족. **이번 구현 범위에서 제외.**

### AI 사용 여부

필요함. **Claude Vision 또는 GPT-4o Vision** API 호출.

### 자동화 수준

**반자동(human-in-the-loop) 필수.**  
AI가 틀릴 수 있으므로 자동 저장이 아닌 수의사 검토 후 승인 흐름.

---

## 구현 파이프라인

```
장비 측정 화면 스크린샷 업로드
        ↓
Vision LLM (Claude/GPT-4o)
        ↓
JSON 추출: { "LVIDd": "38.2mm", "EF": "62%", ... }
        ↓
DB 매핑 테이블 조회 (장비별 용어·단위 교정)
        ↓
우리 echocardio 스키마 필드에 draft 매핑
        ↓
수의사 검토 UI (수정 가능) → 저장
```

---

## DB 매핑 테이블 설계 (예시)

장비마다 같은 항목을 다른 이름으로 표기한다.  
별도 테이블 `echo_field_mappings` 로 관리.

| 우리 필드 | GE Vivid | Philips EPIQ | Mindray | 단위 교정 |
|---|---|---|---|---|
| `lvid_d` | LVIDd | LVEDD | LVDd | mm |
| `lvid_s` | LVIDs | LVESD | LVDs | mm |
| `ef_teich` | EF(Teich) | EF% | EF | % |
| `ivs_d` | IVSd | IVSTd | IVSd | mm |
| `lv_pw_d` | LVPWd | LVPWTd | PWd | mm |
| `e_wave` | E | E vel | E | cm/s |
| `a_wave` | A | A vel | A | cm/s |
| `e_a_ratio` | E/A | E/A ratio | E/A | — |

단위 교정 규칙도 별도 관리 (cm↔mm ×10, m/s↔cm/s ×100 등).

## UI 레이아웃 (목표)

```
┌─────────────────────────────────────────────────────┐
│  [이미지 업로드 영역]      [추출 결과 — 편집 가능]       │
│                                                     │
│  ┌─────────────┐         LVIDd   38.2 mm  ✓        │
│  │  스크린샷   │         LVIDs   24.1 mm  ✓        │
│  │  이미지     │         IVSd     8.3 mm  ✓        │
│  │             │         EF       62 %    ⚠ 검토   │
│  └─────────────┘         E/A      1.4     ✓        │
│                                                     │
│  장비: GE Vivid (자동 감지 or 수동 선택)              │
│                                                     │
│             [취소]  [검토 완료 → 저장]               │
└─────────────────────────────────────────────────────┘
```

신뢰도 낮은 항목(⚠)은 별도 표시해 수의사가 우선 확인하도록 유도.

## 구현 난이도 분류

| 항목 | 난이도 | 비고 |
|---|---|---|
| 이미지 업로드 UI | 낮음 | cytology 업로더 패턴 재사용 가능 |
| Vision API 호출 | 중간 | 프롬프트 엔지니어링 + 파싱 |
| OCR 결과 → JSON 파싱 | 중간 | 검증 로직 포함 |
| DB 매핑 테이블 | 중간 | 초기 데이터 입력이 관건 |
| 단위 자동 교정 | 중간 | 변환 규칙 정의 필요 |
| 결과 검토 UI | 낮음 | 수치 확인 후 수동 승인 |
| 장비 자동 감지 | 높음 | 이미지 특성으로 브랜드 판별 — 초기엔 수동 선택으로 |
